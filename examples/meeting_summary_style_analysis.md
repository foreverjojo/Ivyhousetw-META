# Meeting Summary 風格分析（給一般人好 follow）

## 目標
- 讓「會議摘要」更像你提供的 ChatGPT/Gemini 範本：先講重點、可執行、白話、帶門檻。
- 讓讀者不需要懂投放專業名詞，也能照著做。
- 每個建議都要能追溯到輸入資料（避免臆測）。

## 你提供的範本為什麼更好讀
### 1) 結構上：先回答最重要的問題
- 一開始就給 TL;DR（主力是誰、為什麼）。
- 直接回答「今天總預算要不要加？」這種老闆/操盤手最在意的問題。

### 2) 建議上：可操作、可驗收
- 每條建議都包含：要做什麼、為什麼、用哪個數字判斷、什麼情況要停（止損/停損）。
- 提供「比例/公式」讓你能套到自己的總預算（例如 70/20/10）。

### 3) 用詞上：白話、少框架名詞
- 不先講方法論或模型名稱，直接用「今天做什麼」帶讀者走。
- 指標只保留足夠做決策的：CPP/ROAS/CTR(連結)/CPC(連結)/頻次/LPV/Click。

## 建議的「會議摘要」模板（建議放在 meeting.md 最前段）
> 這是模板規格（不是程式實作）。

### A. 這週先講重點（1 分鐘版）
- 1–3 段短文：
  - 主力 ad set / 主力素材是誰
  - 最關鍵 3–6 個數字（花費/購買/CPP/ROAS/CTR/CPC/頻次）

### B. 今天總預算：加 / 不加（結論一句話）
- 給 Yes/No + 一句原因
- 若要加：給加多少（% 或區間）

### C. 今天立刻要做的調整（照做就好）
- 3–6 條條列
- 每條都要包含：
  - 動作：加碼/降碼/暫停/複製測試
  - 原因：引用哪個數字或哪個現象
  - 門檻：什麼狀況算成功/什麼狀況要停

### D. 下次回來我看這 3 個數字（驗收門檻）
- 例如：CPP ≤ X、頻次 < Y、ROAS > Z
- 滿足條件才擴量；不滿足就先修正/換素材

### E. 風險檢查（必做 2 件事）
- 對帳：官網營收 vs Meta 回傳金額，差距 > 20% 時如何解讀
- 疲勞：頻次 > 3 且 CTR 下滑時的處置

## 資料來源 mapping（避免憑空建議）
- 主力/弱勢 ad set / ad：優先從 report_summary.tables（top/bottom）或 report_insights 的重點匯整。
- 預算比例/搬家建議：來自「主力 vs 其他」的效率差（CPP/ROAS/CTR/CPC）+ 風險控管（頻次、轉換品質）。
- 門檻（例如 CPP ≤ 250、頻次 < 3）：
  - 先採用預設門檻；後續可開成設定值（讓你可調）。
- 風險檢查：
  - purchase value 回傳/對帳差距
  - fatigue（頻次/CTR 走勢）

## 下一步討論（需要你確認的內容）
1) 你想要「摘要」的固定段落是否就是 A~E？有沒有要增減？
2) 你想固定用哪些指標做門檻（CPP/ROAS/CTR/CPC/頻次/LPV/Click…）？
3) 你偏好用「比例」還是「具體金額」來說預算調整？
4) 你希望語氣更像 chatgpt.txt（更直接命令式）還是介於 chatgpt/gemini 之間？
