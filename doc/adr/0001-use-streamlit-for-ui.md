# ADR-0001: 採用 Streamlit 作為 UI 框架

## 狀態

✅ 已接受

## 背景

專案需要快速搭建數據分析 UI，讓使用者能夠：
- 上傳 Meta 廣告報表（CSV）
- 查看 KPI 計算結果
- 獲取 AI 顧問建議
- 生成週會報告

團隊規模為 1 人，需要快速原型開發能力。

## 決策

採用 **Streamlit** 作為 UI 框架，而非傳統的 Flask + 前端框架組合。

## 理由

1. **開發速度**：純 Python 開發，無需寫 HTML/CSS/JavaScript
2. **學習曲線**：團隊成員熟悉 Python，無需學習前端技術
3. **社區成熟**：豐富的元件庫和文檔
4. **部署簡單**：可直接部署到 Streamlit Cloud 或容器化
5. **數據展示**：內建圖表和表格元件，適合數據分析場景

## 後果

### 優點

- 開發速度快（原本預估 2 週的 UI，用 Streamlit 只需 3 天）
- 代碼簡潔，易於維護
- 與 Pandas 整合良好

### 缺點

- 自定義 UI 受限（無法做複雜的前端互動）
- Session State 管理較為原始
- 每次互動會重新執行整個腳本（需要使用快取）

## 替代方案

### 方案 A: Flask + React

**描述**：傳統的前後端分離架構

**未採用原因**：
- 開發成本過高（需要同時維護前後端）
- 團隊無前端專家
- 原型階段不需要複雜的前端功能

### 方案 B: Dash by Plotly

**描述**：另一個 Python 數據儀表板框架

**未採用原因**：
- 功能不如 Streamlit 直覺
- 社區較小，文檔較少
- 與專案需求的匹配度較低

### 方案 C: Gradio

**描述**：快速 ML Demo 框架

**未採用原因**：
- 更適合 ML 模型展示，而非完整的商業應用
- 缺乏多頁面支援（當時）
